# タスク管理 DB スキーマ(Notion)

**このファイルの役割**: Notion にタスク用 DB を作る日が来たら、この定義通りに 1 個だけ
作る。Notion MCP 接続時に「このスキーマでタスク DB を作って」と言えばそのまま作れる。
既存の散らかったページ・DB は触らない・移行しない(必要になったタスクだけ都度移す)。

## DB 名

タスク

## プロパティ定義

| プロパティ | 型 | 選択肢(統制語彙・SKILL.md と完全一致させる) |
|---|---|---|
| タスク名 | Title | — |
| カテゴリ | Select | 仕事 / 大学院 / 私用 |
| 緊急度 | Select | 至急(今日中) / 今週 / それ以降・期限なし |
| 所要時間 | Select | 短(〜15分) / 中(〜1時間) / 長(1時間超) |
| 期限 | Date | — |
| 状況 | Select | 未着手 / 進行中 / 完了 / 待ち |
| 待ち先 | Text | 「待ち」のときのみ(例: ○○事務所の回答待ち) |
| 最初の一手 | Text | 長タスクのみ(15〜30分でできる最初の一歩) |
| 出どころ | Select | 思いつき / ゼミ宿題 / 打合せ宿題 / その他 |
| 追加日 | Date | — |

## 運用ルール

- **完了タスクは消さない・アーカイブしない。** ビュー側で「状況 ≠ 完了」フィルタを
  掛けて隠す(あとで週報・月報の材料になる — work-report-writer で使える)
- 推奨ビュー:
  1. **今日**: 緊急度 = 至急、状況 ≠ 完了
  2. **隙間時間**: 所要時間 = 短、状況 ≠ 完了
  3. **待ち**: 状況 = 待ち(週 1 回見て、動きが無ければ催促を検討)
- 「出どころ」を付けておくと、ゼミ宿題(advisor-meeting-logger)・打合せ宿題
  (meeting-record-keeper)の対応状況を横断で確認できる
