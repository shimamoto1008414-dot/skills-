# Skill Creator(このリポジトリ用)

このリポジトリは個人のスキル集である。スキルの新規作成・改善は、必ず以下の
リポジトリ規約に沿って行うこと。

## 1. リポジトリの構成

```
Academic/                    研究・大学院関係のスキル
  shared/                    複数スキルで共有する参照ファイルの実体
  academic-paper-translator/ 論文を読む・訳す
  literature-review-assistant/ 文献レビューを記録・蓄積する
  academic-document-formatter/ 自分の発表資料・提出物・メモを作る
work/                        仕事関係のスキル
  homepage-companion/        ホームページ制作の伴走
.claude/skills/              Claude Code のプロジェクトスキル(本スキルなど)
```

各スキルは `スキル名/SKILL.md` +(必要なら)`references/` `assets/` で構成する。
新しいスキルは既存カテゴリ(Academic / work)に入れるか、合わなければ新しい
カテゴリフォルダを作る。どちらか迷う場合はユーザーに確認する。

## 2. 新しいスキルを作る流れ

1. **ヒアリング** — いきなり書き始めない。まず次を確認する:
   - そのスキルで何ができるようになってほしいか(具体的な依頼例を 2〜3 個)
   - 出力の形(md / docx / pptx / 会話での伴走 など)
   - 既存スキルとの境界(既存スキルと役割が重なるなら、どちらが担当するか)
2. **設計** — SKILL.md 本体には「判定ロジックと共通ルール」だけを書き、
   詳細な手順・テンプレートは `references/` に分割する(トークン節約のため、
   使わない reference は読まない設計にする)。既存スキルの構成が手本:
   - 用途→参照ファイルの対応表を SKILL.md に置く(academic-document-formatter 方式)
   - フェーズ→参照ファイルの対応表を置く(homepage-companion 方式)
3. **雛形作成** — `カテゴリ/スキル名/SKILL.md` を作り、必要に応じて
   `references/` `assets/` を足す。
4. **description の作り込み**(下記 §4)。
5. **チェック**(下記 §7)をしてからコミットする。

## 3. SKILL.md の書き方

### frontmatter(YAML)
- `name`: 小文字英数字とハイフンのみ、64 文字以内、**フォルダ名と一致させる**。
- `description`: 1024 文字以内。「何をするか」+「いつ使うか(ユーザーの言い回し例)」
  +「対象外(他スキルとの境界)」を入れる。複数行になるときは `>-` を使う。
- それ以外のキーは原則使わない。

### 本文
- 日本語で書く(このリポジトリの規約)。
- SKILL.md 本体は短く保つ。長くなる詳細は `references/` に逃がし、
  「該当する 1 ファイルだけを読み込むこと」と本文に明記する。
- ユーザーが用途を明言していない場合の確認方針(推測で決め打ちしない)を書く。
- 他スキルとの**境界**を明記する(例: 「文献を読む・訳す → academic-paper-translator」)。
  境界が変わる場合は、**相手側のスキルの description・本文も同時に更新**する。

## 4. description のコツ(トリガー精度)

description はスキルが発動するかどうかを決める最重要部分。既存スキルに倣い:

- ユーザーが実際に言いそうなフレーズを鉤括弧で列挙する
  (例: 「ゼミ資料を作って」「発表資料を作って」)。
- 「〜は対象外。○○ は △△ スキルを使うこと」と境界を書き、誤発動を防ぐ。
- 発動しすぎる/しなさすぎる場合は、フレーズの追加・削除と境界の明記で調整する。

## 5. 共有ファイル(symlink)の扱い

複数スキルで同じ参照ファイルを使う場合は、実体を `Academic/shared/` に置き、
各スキルからは**相対パスの symlink** で参照する(既存例: 2 スキルの
`references/research_context.md` → `../../shared/research_context.md`)。

```bash
ln -s ../../shared/ファイル名.md カテゴリ/スキル名/references/ファイル名.md
```

共有ファイルを編集するときは実体(shared 側)を編集する。symlink を通常ファイルで
上書きしないこと。

## 6. claude.ai アップロード用のパッケージ化

claude.ai にアップロードする場合はスキルフォルダを zip にする。symlink は
**実体を含めた形で** 固める必要がある(`zip` はデフォルトで symlink を辿るので
そのままでよい。`tar` を使う場合は `-h` を付ける):

```bash
cd Academic && zip -r スキル名.zip スキル名/
```

zip を展開して `references/` の中身が本物のファイルになっているか確認してから渡す。

## 7. コミット前チェックリスト

- [ ] `name` とフォルダ名が一致している
- [ ] description に「何を・いつ・対象外」が入っている
- [ ] **description が 1024 文字以内**(超えると claude.ai にアップロードできない。
  折り返し行を 1 行に結合した文字数で数える。900 字を超えたら削る側に倒す)
- [ ] SKILL.md 本体は判定ロジック+共通ルールのみで、詳細は references/ に分割した
- [ ] 境界が変わった場合、関係する他スキルも更新した
- [ ] symlink が相対パスで、リンク切れしていない(`ls -la` で確認)
- [ ] コミットメッセージは既存に倣い英語(例: `Add ○○ skill to Academic folder`)
