# レジュメ(配布・報告用のまとめ資料・docx)の作成ルール

「配布して読ませる」様式のときに使う。**場面は問わない**(合同ゼミの文献紹介レジュメ、
授業の課題レジュメ、ゼミでの進捗報告レジュメなど、配布資料ならこのファイル)。
投影して口頭発表する「スライド」は様式が異なるので `reference/slide.md` を使うこと。

## 前提
- docx スキル(`/mnt/skills/public/docx/SKILL.md`)が利用可能な環境では、
  必ずそちらを読み込み、その作法に従って docx を生成する。

## レジュメの型

レジュメには大きく2系統ある。**ヘッダーと本文の骨格が異なる**ので、どちらかを見極める
(判断がつかなければ一言確認する)。

### A. 文献紹介・報告レジュメ(合同ゼミ・輪読・進捗報告など)
1. **ヘッダー情報**(冒頭にまとめて記載)
   - 日付・発表の場(ゼミ名など)・発表者氏名(所属は必要なら)
2. **紹介文献の書誌情報**(文献紹介の場合)— 著者・年・タイトル・掲載誌・DOI。必要なら邦題。
3. **選定理由**(文献紹介の場合)— なぜこの文献か。自分の研究との関わりを書く。
4. **本文** — 元文献の構成(序論・方法・結果・考察・結論など)に沿って要約・整理する。
5. **議論したい点 / 所感**(あれば)— 末尾に置くと質疑が機能しやすい。

### B. 課題提出用レジュメ(授業の設問応答)
1. **ヘッダー情報**(冒頭にまとめて記載)
   - 提出先: 授業名・担当教員名
   - 提出者: 氏名・学籍番号・所属(研究科・専攻)
     - 学籍番号は **21A260022**(本人の学籍番号。氏名・所属は作成時に確認する)。
   - 提出日
2. **課題(設問)の明示** — 出題された設問をそのまま、または要約して冒頭に書く。
   採点者が「どの設問への応答か」を探さずに済むようにする。
3. **本文** — 設問への応答が明確にわかる構成にする。
   - 設問が複数ある場合は、設問ごとに見出しを立てて対応関係を 1 対 1 にする。
   - 結論(答え)を先に述べ、根拠・展開を後に続ける。

**参考文献**(どちらの系統でも、使用した場合のみ)— 末尾にまとめる。
書式は `reference/report.md` の「参考文献書式(太田貴大先生の論文書式)」に従う。

## 体裁ルール(徹底事項)
- 本文フォントは **MS明朝 10.5pt**。見出しは MSゴシック太字(サイズは本文+1〜2pt)。
- 文字は**黒一色のみ**。色文字・マーカー・下線装飾は使わない。
- 罫線・囲み線・背景色は使わない。ヘッダー情報も線で囲まず、行頭に項目名を置くだけにする。
- 見出しは太字+フォントサイズの差のみで階層を表現する。
- 余白は標準のまま。行間はやや広め(1.15〜1.5)で読みやすさを確保。
- 分量指定(字数・ページ数)がある場合はそれを最優先し、超過も不足もさせない。
