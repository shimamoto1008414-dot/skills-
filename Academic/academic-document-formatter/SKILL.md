# Academic Document Formatter

大学院の研究・ゼミ活動用の文書を、**文書の様式**に応じて 4 種類に作り分けるスキル。
本ファイルは判定ロジックと共通ルールのみ。様式別の詳細ルールは `reference/` 配下に
分離してあるので、**該当する 1 ファイルだけを読み込む**こと(トークン節約のため、
使わない reference は読まない)。

## 1. 文書の「様式」で判定する(場面では分けない)

**重要:「ゼミだからスライド」「授業だからレジュメ」ではない。**
同じ「ゼミ」でも、投影用のスライド(pptx)を作ることもあれば、配布用のレジュメ(docx)を
作ることもある。逆に授業でスライドを、学会でレジュメを作ることもある。
出力フォーマットは**場面(ゼミ / 授業 / 学会 / 提出)ではなく、作ろうとしている
文書の様式**で決める。

| 文書の様式 | 出力フォーマット | 読み込む参照ファイル |
|---|---|---|
| スライド(投影・口頭発表用) | pptx | `reference/slide.md` |
| レジュメ(配布・報告用のまとめ資料) | docx | `reference/resume.md` |
| レポート(論述・提出用の文章) | docx | `reference/report.md` |
| 原稿(発表で読み上げる台本。自分用) | docx(基本)または md | `reference/script.md` |
| メモ・下書き(自分用) | docx(基本)または md | `reference/personal.md` |

判定の手がかり(**様式を表す語**に注目する。場面を表す語だけで決めない):
- 「スライド」「パワポ」「pptx」「投影」「◯枚で」→ スライド(pptx)
- 「レジュメ」「配布資料」「ハンドアウト」「まとめ(1〜数枚の資料)」「報告資料」→ レジュメ(docx)
- 「レポート」「論述」「◯字で」「期末」「提出用の文章」→ レポート(docx)
- 「原稿」「発表原稿」「読み上げ」「台本」「カンペ」「話す内容」→ 原稿(基本は docx。明示指定があれば md)
- 「メモ」「下書き」「自分用」「整理したい」→ 自分用メモ(基本は docx。明示指定があれば md)
- 「ゼミ」「合同ゼミ」「授業」「発表」「学会」などは**場面を表す語であって、様式は決めない**。
  これらの語だけがあって様式が読み取れないときは、決め打ちせず様式を一言だけ確認する。
  (例:「投影するスライド(pptx)ですか、配布するレジュメ(docx)ですか?」)

**ユーザーが様式を明言していない場合は、推測で決め打ちせず、まず一言だけ確認する。**
様式が確定したら、対応する reference ファイルを読んでから作成に入る。

## 2. 共通の書式ルール

### 提出・発表用(slide / resume / report 共通)
- docx の本文は **MS明朝 10.5pt**、pptx は **16:9・本文 18pt 以上**(詳細は各 reference)。
- 文字は**黒一色のみ**。強調は太字・フォントサイズ・階層で表現し、色文字は使わない。
- 装飾的な罫線・囲み線・背景色は使わない(表の必要最小限の罫線は可)。
- レイアウトはできるだけシンプルに。**余白と見出しの階層構造**で情報を整理する。

### 自分用(script / personal)
- 配布・提出しない自分用の文書(原稿・メモ)。体裁の厳密さより実用性を優先する。
- 薄いグレーなど目立たない色で、注釈・ト書き・コメントを本文と区別して入れてよい。
- 思考の途中経過・疑問点・TODO、読み上げ用のト書きなどをそのまま残してよい。
- 原稿は「読み上げやすさ・時間管理」、メモは「後で見返せる自由度」を優先する。

## 3. 他スキルとの連携・境界

- pptx 生成時は pptx スキル(`/mnt/skills/public/pptx/SKILL.md`)、docx 生成時は
  docx スキル(`/mnt/skills/public/docx/SKILL.md`)が利用可能ならそちらの作法に従う。
- **境界**: 文献を読む・訳す → `academic-paper-translator`。
  文献レビューを記録・蓄積する → `literature-review-assistant`。
  ゼミ・指導で受けたコメントを記録・追跡する → `advisor-meeting-logger`。
  自分の発表資料・提出物・メモを作る → 本スキル。
