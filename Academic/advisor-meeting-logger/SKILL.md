# Advisor Meeting Logger

ゼミ・指導記録を毎回同じ形で蓄積するワークフロー。指導記録の価値は
「言われたことが揃った形で残り、未対応が一目で見えること」にある。
記憶と脚色に頼った記録は、修論の方針がぶれたときに役に立たない。

## Step 0: モード判定

- **記録モード** — ゼミ・面談直後の生メモ、録音の文字起こし、口頭での報告を
  渡された → Step 1 へ
- **照会モード** — 「前回何を言われた?」「未対応は?」 → 過去記録から抽出する。
  記録が渡されていなければ、Notion MCP 接続時は DB 検索を提案し、
  未接続なら過去ノートの貼り付けを一度だけ依頼する
- **準備モード** — 「次のゼミの準備」 → 未対応 TODO と前回の「次回に向けて」から
  議題リストを生成する

## Step 1: 記録の原則

- `references/research_context.md` を読み、各指摘が研究のどこに効くかを添える
  (RQ / 方法・尺度 / 文献 / 書き方 / 手続き・スケジュール)
- **「言われたこと」と「自分の解釈」を必ず分ける。** 曖昧だった指摘は解釈で
  埋めず「要確認」として次回議題に回す
- ユーザーは実務と両立していて時間が無い。日付・種別が不明なら文脈から
  推定して「(推定)」と付け、確認質問でブロックしない

## Step 2: 記録生成(固定テンプレート・日本語)

Notion の「プロパティ」と「ページ本文」は貼り付け挙動が別物なので、
literature-review-assistant と同じく必ず 2 部構成で出す。

### プロパティ部

| プロパティ | 値 |
|---|---|
| Title | YYYY-MM-DD 種別(例: 2026-07-15 ゼミ発表) |
| 日付 | YYYY-MM-DD |
| 種別 | ゼミ発表 / 個別指導 / 授業コメント / メール指導 |
| 指導者 | 太田先生 / その他(名前) |
| 主な論点 | 3個まで(例: RQの絞り込み、尺度選定) |
| 対応状況 | 未対応あり / すべて対応済 / 保留あり |
| 追加日 | YYYY-MM-DD |

### 本文部

```
## 当日の要旨
(自分が何を報告・発表したか、1〜3行)
## 指摘・コメント
(発言のニュアンスを保って箇条書き。複数人なら発言者名を付す。脚色しない)
## 解釈・背景
(指摘の意図の推測。推測は推測と明記する)
## TODO
- [ ] 内容(期限: MM/DD / 状況: 未対応)
## 方針への影響 ★最重要
(この指導で研究計画の何が変わるか・変わらないかを具体的に)
## 次回に向けて
(次回の報告予定・確認したいこと・「要確認」の曖昧な指摘)
```

TODO の状況は統制語彙からのみ選ぶ(表記ゆれ防止):
**未対応 / 対応中 / 対応済 / 保留(方針待ち)**

## Step 3: 出力と Notion 連携

1. まず記録を**必ずチャットに出力する**(確認待ちで出力を止めない)
2. Notion MCP 接続時のみ、出力後に「このまま登録しますか?」と一度だけ提案する。
   無断でページを作成しない
3. 登録時はプロパティ名を上の表と完全一致させる
4. 照会・準備モードで過去記録を読むときは「対応状況」と「TODO」を優先して見る

## 言語ルール

記録は日本語で書く。指摘に英語の用語・文献名が含まれる場合は
「日本語訳 (原語)」形式、書誌情報は原語のまま(literature-review-assistant と同じ規則)。
