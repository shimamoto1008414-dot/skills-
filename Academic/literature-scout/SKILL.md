# Literature Scout(課題対応・文献探索)

先生からの「まとめて」「調べて」に対して、闇雲に検索を始めないためのワークフロー。
**解釈 → 読むものの設計 → 収集 → 入手経路の確認** の順で動く。

## 鉄則(全ステップ共通)

- **実在する文献だけを挙げる。** 書誌(著者・年・タイトル・誌名)は必ず検索結果から
  取り、記憶で書かない。実在確認できなければリストに入れず、
  「見つからなかった」と正直に言う
- 所蔵・貸出状況は OPAC の検索結果だけを根拠にする。推測で「あるはず」と言わない
- 各文献に「なぜ読むのか」1 行を必ず付ける(理由のないリストは読まれない)

## Step 1: 課題の解釈(すぐ検索しない)

`references/research_context.md` を読んでから:

1. **課題の型を判定**: 概念整理(「〜についてまとめて」)/ 文献調査(「先行研究を
   調べて」)/ 発表準備(「次回発表して」)
2. **自分の研究との接続を明示した解釈を出す**(例: 「人のプライバシーについて
   まとめて」→ 人のプライバシー論は動物のプライバシー研究の理論的基盤。
   概念の定義・系譜を軸に、最後に動物への拡張可能性へ橋を架ける構成が有効)
3. **まとめの構成案(見出しレベル)を先に提示し、合意を得てから収集に入る。**
   方向がずれたまま集めると全部無駄になる。確認はこの 1 回だけに絞る

## Step 2: 読むものの設計

- 構成の基本形: 基本書・入門書(1〜2冊)+ 古典・原典(1〜2)+ レビュー論文(1〜2)
  + 近年の論文(2〜3)
- 実務と両立中なので、**コア(必読・5 点以内)**と**追加(余裕があれば)**に分ける
- 日本語文献を入口にし、英語文献は academic-paper-translator で読む前提で選んでよい

## Step 3: 収集(サブエージェント活用)

**Agent ツール(サブエージェント)が使える環境では、「論文収集」と「図書の所蔵検索」を
別々のサブエージェントに任せて並列で進める。** 使えなければ自分で順に検索する。
Web 検索自体が使えない環境では、`references/search_guide.md` の検索語セットを
そのまま出力して手動検索を案内する。

検索先・検索語の設計・報告書式は `references/search_guide.md` を読むこと。

- **論文** — 成果: 書誌 / 入手経路(OA の PDF・DOI・J-STAGE 等のリンク)/
  位置づけ 1 行 / 読む順
- **本** — 大阪大学 OPAC で所蔵検索。成果: 所蔵館(キャンパス付き)/ 配架場所・
  請求記号 / 貸出状況(確認できた場合)。
  **人間科学研究科は吹田キャンパスなので、所蔵館がどこかは必ず書く**(豊中の
  総合図書館所蔵なら移動が必要)。確認しきれない項目は「OPAC で要確認」とし、
  OPAC の検索リンクを添える
- 所蔵なし・貸出中の場合の代替も添える: 電子ブックの有無 / ILL(他館取り寄せ)/
  購入希望 / 購入(価格目安)

## Step 4: 成果物(課題対応パッケージ)

```
# 課題対応: (課題の一言要約)
## 課題の解釈と構成案
(Step 1 で合意したもの)
## 読書リスト
### コア(必読・読む順)
1. 文献(種別 / なぜ読むか / 入手: リンク or 所蔵館・配架・請求記号)
### 追加(余裕があれば)
## 次のアクション
- 図書館で借りる本(どの館に行くか)
- 今日ダウンロードできる論文
- 読了後: literature-review-assistant でノート化 → まとめは
  academic-document-formatter で文書化
```

## 他スキルへの導線

英語論文を読む → academic-paper-translator / 読んだら記録 → literature-review-assistant /
まとめを文書にする → academic-document-formatter / 課題の出どころ(指導コメント)の
記録 → advisor-meeting-logger
