# ③ 制作フェーズ

土台ができたので、いよいよ「見た目」と「中身」を作ります。ここでユーザーの満足度が大きく決まります。**クオリティと視覚的な見やすさを最優先**に、サブエージェントとプレビューを積極的に使ってください。

## 進める順番

1. **デザインの方向性を決める**（テーマ選び・配色・雰囲気）
2. **トップページから作る**（サイトの顔。ここで世界観を確定）
3. **残りのページを作る**（企画で決めたサイトマップ順に）
4. **全体の見た目を整える**（カスタムCSSで仕上げ）

各ページは「①構成 → ②文章 → ③写真 → ④見た目の調整」の順。完璧を目指さず、まず形にして、見ながら直すスタイルが初心者に合います。

## WordPressでの作り方の基本（初心者へ説明）

WordPressでは、主に次の3つの方法で見た目と中身を作ります。ユーザーのテーマによって使うものが変わります。

- **テーマ** = サイト全体のデザインの「ひな形・着せ替え」。まずこれを選ぶ。
- **ブロックエディタ（Gutenberg）** = 文章・画像・ボタンなどを「ブロック」を積むように置いていく編集画面。コード不要。
- **カスタムCSS／カスタムHTMLブロック** = 細かい見た目の調整や、特別なパーツを作るためのコード。ここはあなた（Claude）が書いて、ユーザーに貼り付けてもらう。

> あなたはWordPress管理画面を直接クリックできません。**「文章・コードを用意する人」**として動き、「この文章をこのページに貼ってください」「このCSSを〇〇に貼ってください」と1ステップずつ案内します。貼る場所（例：外観 → カスタマイズ → 追加CSS）まで具体的に。

## テーマ選び

- お店・会社紹介向けに、**シンプルで日本語表示がきれい・カスタマイズしやすい**無料テーマを2〜3個、特徴を添えて提案する（例：Cocoon、Lightning、Astra など。最新の定番はWeb検索で確認するとよい）。
- 「テーマは後から変えられますが、変えると見た目が大きく変わるので、最初にしっくりくるものを選びましょう」と伝える。
- 選んだら、インストール＆有効化の手順を1ステップずつ案内。

## デザイン作業の進め方（サブエージェント＋プレビュー）

ここが品質の要です。**見た目を設計する作業は、サブエージェント（Agentツール）に任せて品質を上げ、プレビューを見せてから実装**します（プレビューの出し方は SKILL.md の「プレビューの出し方」）。文字で「青系の落ち着いたデザインにします」と言うだけでは、初心者は完成像を描けません。**見て選んでもらう**のが鉄則です。

### 手順

1. **方向性をユーザーから引き出す**：参考にしたい雰囲気、好きな色、避けたい印象を聞く（企画フェーズのメモも参照）。
2. **サブエージェントにデザイン案を作らせる**：例えばトップページのヒーロー（最上部の大きな見出し画像）や、3つの強みを並べるセクションなど。依頼は具体的に（下記テンプレ参照）。複数案がほしいときは複数のサブエージェントを並行で走らせる。
3. **プレビュー表示**：サブエージェントが作ったHTML/CSSを、実際の見た目としてユーザーに見せる。「A案・B案、どちらが好みですか？」と選んでもらう。
4. **合意できたら実装に変換**：選ばれたデザインを、WordPressで再現する形（テーマの設定＋カスタムCSS＋カスタムHTMLブロック）に落とし込み、貼り付け手順を案内する。

### サブエージェントへの依頼テンプレート（デザイン）

```
あなたはプロのWebデザイナーです。お店・会社紹介サイトの「（部分名：例 トップページのヒーローセクション）」の
デザイン案を、HTML+CSS（1ファイル完結、CSS変数で配色管理）で作ってください。

- 業種・お店の雰囲気：（例：地域密着の手作りパン屋、温かみ・親しみやすさ）
- 載せる要素：（例：キャッチコピー、店名、来店を促すボタン、背景に外観写真の想定）
- トーン＆配色：（例：ベージュ＋ブラウン系、丸みのある書体、余白広め）
- 制約：レスポンシブ（スマホで見やすい）、文字の可読性、過度な装飾は避ける
- 写真は仮のプレースホルダでよい

視覚的な美しさ・見やすさ・余白の取り方を最優先してください。完成したHTMLを返してください。
```

返ってきたHTMLは、メインの会話でプレビューとしてユーザーに見せます（必ず見せてから進む）。

### 視覚品質のチェック観点（サブエージェントにもユーザー確認にも）

- スマホで見て崩れない・読みやすい（多くの人はスマホで見る）
- 文字と背景のコントラストが十分（読みやすさ・アクセシビリティ）
- 余白が窮屈でない／詰め込みすぎていない
- 配色は2〜3色＋アクセント1色程度に絞る
- 一番伝えたいこと（キャッチコピー、電話・予約ボタン）が目立つ位置にある
- 写真の質感がそろっている

## 文章（コンテンツ）作り

- 各ページの文章は、企画フェーズのメモをもとに**あなたが下書きを書いて**、ユーザーに確認・修正してもらう形が最速。初心者は「ゼロから書く」のが一番つらいので、たたき台を出してあげる。
- 複数ページぶんをまとめて作るときは、サブエージェントに各ページの文章ドラフトを並行で作らせると効率的（ただしお店固有の事実＝住所・料金・電話などは必ずユーザーに確認した正確な情報を使う。創作で埋めない）。
- 文章のコツをユーザーにも共有：「専門用語より分かる言葉」「お客さん目線」「一番言いたいことを最初に」「行動（電話・予約）への一言を添える」。

## 写真について

- 写真はサイトの印象を大きく左右する。今ある写真を聞き、足りなければ「明るい時間に正面から」「スマホで十分」など撮り方を助言。
- 重い画像はサイトを遅くするので、アップ前にサイズを整える（横幅1600px程度・適度な圧縮）よう案内。WordPress側の最適化プラグインも選択肢。
- 他人の写真・ネットの画像を勝手に使わない（著作権）。フリー素材を使うなら出所が明確なものを、と注意を伝える。

## ページを1枚ずつ仕上げる

トップページが固まったら、それを基準に各ページを作ります。毎回このリズムで：

1. このページの目的とゴールを再確認（例：アクセスページ＝来店してもらう）
2. 構成（載せる要素の順番）を決める
3. 文章ドラフトを出して確認
4. 必要な見た目はサブエージェント＋プレビューで
5. WordPressへの反映手順を1ステップずつ案内
6. 実際の画面で確認 → 次のページへ

## 完了の合図

サイトマップの全ページが、文章・写真・見た目そろって表示できる状態になったら制作フェーズは完了です。「形になりました！公開する前に、一緒に最終チェックをしましょう」と伝え、`references/04-launch.md` へ進みます。

## つまずき・声かけ

- **見た目がしっくりこない** → 文字で議論せず、サブエージェントで別案を作ってプレビュー比較。「言葉より見て選びましょう」。
- **作業が長く感じて疲れる** → 「今日はトップページまで」など区切りを設け、現在地を残して休む。
- **コード貼り付けが怖い** → 「貼る前にバックアップを取ります」「ダメなら消せば元通りです」と安心させてから。
