# ⑥ 構成追加・改修フェーズ

公開後、サイトを育てていく段階です。「ページを増やしたい」「予約フォームを付けたい」「ブログを始めたい」「デザインを今っぽくしたい」——こうした相談はここで扱います。一度サイトを作った経験があるとはいえ、新しいことは毎回少し不安なので、**最初に作ったときと同じ伴走の丁寧さ**を保ってください。

## 改修の前に必ず：バックアップ

既存の動いているサイトに手を入れます。**何かあっても戻せるよう、作業前に必ずバックアップ**を取ってもらってください。「今あるものを壊さないために、まず写しを取ります」と毎回声をかけます。これが改修フェーズの鉄則です。

## まず「小さな企画」をする

新しいページや機能も、①企画フェーズの小型版から始めます。いきなり作らず、次を一緒に言葉にします。

- **目的**：それを足すと、誰の何が良くなるのか？（例：予約フォーム＝電話できない時間帯のお客さんを取りこぼさない）
- **置き場所**：どのメニュー・どのページに入れるか。既存の構成のどこに収まるか。
- **必要な要素**：そのページ／機能に何を載せるか。
- **優先度**：本当に今必要か。「あったらいいな」を全部足すとサイトが散らかる。**1つずつ**追加するよう勧める。

## よくある追加と進め方

### ページを増やす（例：採用情報、よくある質問、お客様の声）

1. 企画（上記）で目的と中身を固める
2. 既存ページと同じ作り方で1枚作る（`references/03-building.md` のリズム）
3. メニューに追加して、たどり着けるようにする
4. スマホ・PCで表示確認

### 機能を足す（例：予約フォーム、ネット予約、地図、Instagram埋め込み、お問い合わせフォーム強化）

- WordPressでは多くの機能を**プラグイン**で足せる。「プラグイン＝スマホのアプリのように、後から機能を追加できる部品」と説明。
- 入れすぎるとサイトが重く・不安定になるので、**本当に必要なものだけ**。目的に合うプラグインを2〜3候補、特徴を添えて提案し、ユーザーに選んでもらう。
- インストール → 設定 → 表示確認、を1ステップずつ案内。設定が複雑なものは、項目ごとに意味を説明しながら進める。

### デザインを変える・今っぽくする

- 見た目の変更は、`references/03-building.md` の「デザイン作業の進め方」と同じく、**サブエージェントで案を作り、`show_widget` でプレビューして選んでもらう**。
- 部分的な変更（色だけ、ボタンだけ）か、全体の刷新（テーマ変更）かで影響範囲が大きく違う。テーマ変更は見た目が大きく変わるので、変更前後をプレビューで見比べてもらい、慎重に。必ずバックアップを取ってから。

### お知らせ・ブログを始める

- 続けられるかが鍵。「月1〜2本でも十分」「ネタは日常の出来事でOK」とハードルを下げる。
- 最初の数本は、あなたが構成や下書きを手伝うと立ち上がりやすい。
- 投稿の作り方（投稿 → 新規追加 → タイトルと本文 → 公開）を1ステップずつ案内。

## 改修後の確認（ミニ公開チェック）

追加・変更したら、`references/04-launch.md` のチェックリストの関連部分を使って確認します。特に：

- スマホ・PCで崩れていないか
- メニューやリンクから新しいページにたどり着けるか
- 既存のページが壊れていないか（変更が他に影響していないか）
- フォームを足したならテスト送信

サブエージェントに「変更後のサイトを点検して、崩れ・リンク切れがないか報告して」と頼むと、見落としを拾えます。

## 完了の声かけ

「サイトがまた一歩良くなりました」と達成を一緒に喜びつつ、改修も保守の一部であることを伝えます。変更内容によっては、保守チェックリスト（`assets/maintenance-checklist.md`）の点検項目を増やす必要があるかもしれない、と添えるとより親切です。
