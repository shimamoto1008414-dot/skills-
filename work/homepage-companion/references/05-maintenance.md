# ⑤ 保守・メンテナンスフェーズ

サイトは「作って終わり」ではなく、車や植物と同じで**お手入れを続けるほど長持ち**します。初心者が見落としがちで、でも一番大事なフェーズです。難しく考えさせず、「月に1回の習慣」くらいの軽さで続けられるように導いてください。

`assets/maintenance-checklist.md` に、定期点検チェックリストのひな形があります。これをユーザーに渡し、習慣化を助けてください。

## なぜ保守が必要か（ユーザーに一言で）

- **放置すると危ない**：WordPressやプラグインは古くなると、乗っ取りやウイルスの入口になりやすい。更新は「家の鍵を新しくする」のと同じ。
- **情報が古いと信頼を失う**：営業時間や料金が古いままだと、お客さんに迷惑＆不信感。
- **壊れたときに戻せるように**：バックアップがあれば、何かあっても巻き戻せる。

## 保守の4本柱

### 1. バックアップ（最優先）

- **バックアップ** = サイトの「写し」を別の場所に保存しておくこと。何かあっても、この写しから元に戻せる。
- 自動バックアップのプラグイン（例：UpdraftPlus など）を入れ、**自動で定期的に**取れるよう設定するのがおすすめ。手順を1ステップずつ案内する。
- 「更新作業や大きな変更の前は、必ず手動でも1回バックアップ」を習慣に。あなたがコードを貼ってもらう前にも、毎回「まずバックアップを取りましょう」と声をかける。

### 2. 更新（アップデート）

- WordPress本体・テーマ・プラグインには、ときどき「更新があります」の通知が出る。これは不具合修正や安全対策。**こまめに更新**するのが基本。
- ただし**更新前にバックアップ**。まれに更新で見た目が崩れることがあるため。
- 「更新ボタンを押す → サイトを開いて崩れていないか確認」をセットで案内する。

### 3. セキュリティ（安全対策）

- **強いパスワード**を使う（推測されにくい長いもの）。使い回さない。
- 不要なプラグイン・テーマは削除（使っていない入口は閉じる）。
- ログインを守るプラグインや、迷惑コメント対策を入れると安心。
- 「管理画面のユーザー名を `admin` のままにしない」など基本も案内。

### 4. 情報の更新・運用

- 営業時間・定休日・料金・キャンペーンなど、変わったらすぐ直す。
- お知らせ／ブログを書くと、サイトが「生きている」印象になり、検索にも良い。続けられるペースで。
- 文章のたたき台が必要なら、あなたが下書きを書いてあげる。

## 定期点検のリズム（提案）

ユーザーに無理のない頻度を提案します。目安：

- **毎月1回**：更新の通知を確認して更新／バックアップが取れているか確認／情報が古くないか見直し
- **半年に1回**：全ページをスマホ・PCで見て崩れチェック／リンク切れ確認／使っていないプラグイン整理
- **随時**：営業情報が変わったとき、お知らせを出すとき

カレンダーやリマインダーに「サイトの月1点検」を入れることを勧めてください（リマインダーやカレンダー登録を支援するツールが使える環境なら、その場で設定を手伝う）。

## トラブル対応の基本姿勢

ユーザーが「サイトが表示されない」「エラーが出た」「重い」と来たら、慌てさせず、順番に切り分けます。

1. **状況を具体的に聞く**：いつから／何をした後か／エラー文言（あればそのままコピーしてもらう）／スマホとPC両方か。
2. **直前の操作を疑う**：「直前に更新やコード貼り付けをしましたか？」 → していれば、まずバックアップから戻すのが安全。
3. **よくある原因を確認**：
   - 真っ白・エラー → プラグインやテーマの更新が原因のことが多い。直前に入れた/更新したものを一旦無効化して切り分け。
   - 重い・遅い → 画像が重い／プラグインが多すぎ／キャッシュ系の設定。
   - 表示が崩れた → テーマやCSSの変更が原因。直前の変更を戻す。
4. **戻せる状態を最優先**：迷ったらバックアップから復元。「壊れても写しから戻せます」と安心させる。
5. **手に負えないとき**：サーバー会社のサポートに問い合わせる方法を案内（多くのレンタルサーバーは初心者サポートがある）。

> エラー文言や管理画面のメッセージは、ユーザーにそのままコピーしてもらうと、あなたが原因を特定しやすくなります。「画面に出ている文字をそのまま貼ってください」と頼んでください。

## 完了・継続の声かけ

保守は終わりがありません。「完璧に管理しよう」と気負わせず、「月1回ちょっと見るだけで十分です。何かあれば、いつでも一緒に対応します」と継続のハードルを下げてください。新しいことをしたくなったら ⑥ 改修（`references/06-expansion.md`）へ。
