# Work Report Writer(週報・月報・作業報告)

断片的な作業メモを、毎回同じ形の報告に変換するワークフロー。
報告の価値は「読み手(上司・発注者)が 1 分で状況を把握できること」にある。
書き手の時間短縮と読み手の負荷軽減を両立させる。

## Step 0: 報告タイプの判定

| 依頼の言葉 | タイプ | 単位 |
|---|---|---|
| 「週報」「今週の〜」 | 週報 | 案件・業務ごと |
| 「月報」「今月の〜」 | 月報 | 案件・業務ごと+全体進捗 |
| 「作業報告」「状況報告」「進捗を伝えたい」 | 随時報告 | 対象案件のみ |

タイプが不明なら分量から推定する(1 週間分のメモ → 週報)。確認質問でブロックしない。

## Step 1: 報告の原則

- **事実と予定を分ける。** やったこと(実績)と、やるつもりのこと(予定)を混ぜない
- **未完了を完了と書かない。** 進捗率・完了判断は本人のメモにある申告のみを使い、
  メモに無い進捗を推定で書かない(数字が必要なら「要記入: 進捗率」と placeholder を置く)
- **誇張しない・盛らない。** 定量(枚数・区間・件数)がメモにあれば必ず活かす
- 課題・懸念は隠さず独立セクションに出す。報告で一番読まれるのはここ
- 日付が不明なメモは文脈から推定して「(推定)」と付ける

## Step 2: 生成(固定テンプレート・日本語)

### 週報

```
# 週報(YYYY-MM-DD〜MM-DD)氏名
## 今週の作業実績
(案件・業務ごとに箇条書き。成果物と定量情報を優先)
- [案件名] 作業内容(成果物: ○○ / 進捗: メモの申告値)
## 課題・懸念
(判断待ち・リスク・遅延要因。「誰の判断が必要か」まで書く)
## 来週の予定
(案件ごと。打合せ・提出などの期日イベントを先頭に)
## 連絡事項
(共有のみで対応不要のもの。無ければ「特になし」)
```

### 月報

週報の 4 セクションに加え、先頭に「## 全体進捗」を置く
(案件ごとに 予定比: 順調 / 遅れ(理由) / 前倒し の 3 区分で 1 行ずつ)。

### 随時報告

対象案件のみを「経緯 → 現状 → 課題 → 今後の予定」の 4 部で短く。
メール本文として使える体裁(宛名・挨拶は付けず、依頼があれば付ける)。

## Step 3: 様式対応と運用

1. まず報告を**必ずチャットに出力する**(確認待ちで出力を止めない)
2. **社内様式が最優先。** 様式(Word/Excel/テキスト)を渡してもらえれば以後それに
   合わせて生成する。一度渡された様式の構成はこの skill の運用で固定してよい
3. メモの中に打合せの記録が混ざっていたら、報告には要点だけ入れ、
   「詳細は meeting-record-keeper で記録化しますか?」と一言添える
