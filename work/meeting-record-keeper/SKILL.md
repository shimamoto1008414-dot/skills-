# Meeting Record Keeper(仕事の打合せ簿)

仕事の打合せ記録を毎回同じ形で蓄積するワークフロー。協議記録の価値は
「言った言わないを防ぎ、宿題と担当が一目で見えること」にある。
特に**決定したことと決まっていないことの混同**は実務事故のもとなので、厳密に分ける。

## Step 0: モード判定

- **記録モード** — 打合せ直後のメモ、文字起こし、電話の内容を渡された → Step 1 へ
- **照会モード** — 「前回の宿題は?」「あの件どうなってた?」 → 過去記録から抽出する。
  記録が渡されていなければ、Notion MCP 接続時は DB 検索を提案し、
  未接続なら過去記録の貼り付けを一度だけ依頼する
- **準備モード** — 「次の打合せの準備」 → 未対応の宿題事項と前回の継続協議事項から
  議題リストを生成する

## Step 1: 記録の原則

- **原文を必ず残す。** 渡されたメモ・文字起こしは要約も修正もせず「原文」セクションに
  そのまま保存する。分類はすべて原文から導き、原文に無いことを足さない
- **決定事項と継続協議を厳密に分ける。** 「たぶん決まった」は決定事項に入れず
  継続協議に置き、「要確認」を付ける
- **宿題には必ず担当(自社/先方)を付ける。** 先方待ちの案件が埋もれるのを防ぐ
- 日付・相手先が不明なら文脈から推定して「(推定)」と付け、確認質問でブロックしない

## Step 2: 記録生成(固定テンプレート・日本語)

### プロパティ部

| プロパティ | 値 |
|---|---|
| Title | YYYY-MM-DD 相手先 件名(例: 2026-07-15 ○○事務所 設計条件協議) |
| 日付 | YYYY-MM-DD |
| 種別 | 対面 / Web会議 / 電話 / メール協議 |
| 相手先 | 発注者 / 協力会社 / 社内(組織名も) |
| 出席者 | 先方・自社の順 |
| 主な議題 | 3個まで |
| 対応状況 | 未対応あり / すべて対応済 / 先方待ちあり |
| 追加日 | YYYY-MM-DD |

### 本文部

```
## 原文(そのまま)
(メモ・文字起こしを要約も修正もせずそのまま貼る。誤字も直さない。
 長い場合は Notion のトグルに入れると読みやすい)
## 概要
(何の打合せで、大筋どうなったか。1〜3行)
## 協議事項(原文から分類)
(議題ごとに経緯を箇条書き。発言の根拠となる原文の言葉を「 」で添え、
 重要な発言は発言者名も付す)
## 決定事項
(確定したことだけ。「誰が・いつまでに・何を」の形で)
## 宿題事項(TODO)
- [ ] 内容(担当: 自社/先方 / 期限: MM/DD / 状況: 未対応)
## 継続協議・保留
(決まらなかったこと・次回持ち越し。「要確認」もここに)
## 次回予定
(日時・場所・議題の候補)
```

宿題事項の状況は統制語彙からのみ選ぶ(表記ゆれ防止):
**未対応 / 対応中 / 対応済 / 先方待ち**

## Step 3: 出力と様式対応

1. まず記録を**必ずチャットに出力する**(確認待ちで出力を止めない)
2. 社内様式・発注者指定様式(打合せ簿の Word/Excel 等)がある場合は、
   様式を渡してもらえればそれに合わせて転記した版も出す。様式が常に最優先
3. Notion MCP 接続時のみ、出力後に「このまま登録しますか?」と一度だけ提案する。
   無断でページを作成しない。登録時はプロパティ名を上の表と完全一致させる
4. 照会・準備モードでは「対応状況」「宿題事項」「継続協議」を優先して見る
